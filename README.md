# Скрепка — помощник в Конфигураторе 1С

Окно поверх Конфигуратора. Читает текущий модуль и позицию курсора через
Windows UI Automation, показывает замечания BSL Language Server и по хоткею
складывает контекст для агента.

Работает с обычным **Конфигуратором** — тем самым, у которого нет никакого API
для расширений. Ничего в 1С не устанавливается и не патчится: текст модуля
читается через стандартный Windows UI Automation, код вставляется сообщениями
`WM_CHAR`. Конфигуратор об этом не знает и знать не должен.

## Установка

    pip install -r requirements.txt
    run.bat

Нужен Windows и Python 3.9+. Если 1С запущена от администратора — Python тоже
запускайте от администратора, иначе UI Automation не увидит окно.

Для подсветки ошибок нужен BSL Language Server, см. раздел ниже.

## Хоткеи

| Клавиши | Что делает |
|---|---|
| `Ctrl+Alt+A` | снять контекст в `context\` |
| `Ctrl+Alt+V` | вставить `answer.bsl` в позицию курсора |
| `Ctrl+Alt+S` | спрятать окно / вернуть его |

Нажимать в **Конфигураторе**, курсор — внутри процедуры. Если фокус ушёл,
скрепка использует последнюю запомненную позицию (жёлтая точка).

## Мелочи, которые экономят время

- **Двойной клик по заголовку** — свернуть окно до одной строки: точка, метод,
  позиция. Второй двойной клик разворачивает обратно.
- **Клик по замечанию** — Конфигуратор выходит на передний план и выделяет
  эту строку.
- Позиция и размер окна запоминаются между запусками.
- Кнопки `−1` / `+1` рядом с позицией правят нумерацию строк, если она
  разошлась с Конфигуратором.
- Автозапуск вместе с Windows: `python autostart.py on`
  (выключить — `off`, проверить — `status`). Кладёт .bat в автозагрузку
  текущего пользователя, права администратора не нужны.

## BSL Language Server

Диагностика идёт через живой LSP-процесс: сервер поднимается один раз и держится,
поэтому проверка занимает десятки миллисекунд, а не секунды на перезапуск JVM.

**Важно:** у сервера параметр `computeTrigger` по умолчанию `onSave`, а скрепка
файл не сохраняет — поэтому в комплекте лежит `.bsl-language-server.json`
с `onType`, и он передаётся серверу через `-c`. Без этого сервер запустится,
отработает и не пришлёт ни одного замечания.

Где взять сам сервер, одно из двух:

1. Установлен **Phoenix BSL** — скрепка сама найдёт его лаунчер
   (`...\phoenixbsl\app\bsl-language-server\bsl-language-server.exe`),
   вместе с собственной JRE. Java в системе не нужна.
2. Иначе — `python fetch_bslls.py` скачает jar в папку проекта.
   Тут уже понадобится Java 17+ в `PATH` или `JAVA_HOME`.

Абсолютные пути из `clip.config.json`, которых нет на новой машине,
игнорируются: `workdir` подменяется на папку скрипта, `bslLsJar` — на автопоиск.
Ничего править руками не надо.

Для офлайн-переноса можно положить колесо `comtypes-*.whl` в `vendor\` —
скрепка распакует его сама при первом запуске, и pip не понадобится.
В репозиторий колесо не входит.

## Файлы

| Файл | Зачем |
|---|---|
| `clip.py` | само окно, чтение Конфигуратора, вставка кода |
| `bslls.py` | LSP-клиент к BSL Language Server |
| `probe_1c.py` | диагностика: что вообще видно в окне Конфигуратора |
| `fetch_bslls.py` | загрузка языкового сервера |
| `autostart.py` | запуск вместе с Windows |
| `.bsl-language-server.json` | настройки анализатора; `computeTrigger` тут обязателен |
| `clip.config.json` | настройки, создаётся при первом запуске |
| `vendor\` | место для колеса comtypes при офлайн-установке |
| `context\` | сюда пишется контекст для агента — **в git не попадает** |
| `answer.bsl` | код, который вставит `Ctrl+Alt+V` — **в git не попадает** |

## Настройки (`clip.config.json`)

| Ключ | Смысл |
|---|---|
| `workdir` | рабочая папка; пусто — папка скрипта |
| `answerFile` | откуда брать код для вставки |
| `navigatorName` | имя внешнего навигатора по конфигурации для индикатора в шапке; пусто — не показывать |
| `navigatorUrl` | его адрес, напр. `http://127.0.0.1:8765`; пусто — выключено |
| `pollMs` | как часто опрашивать фокус |
| `stripIndentOnInsert` | срезать отступы при вставке (редактор ставит свои) |
| `bslLsJar` | путь к серверу; пусто — искать самим |
| `javaCommand` | своя java; пусто — из `PATH`/`JAVA_HOME` |
| `diagMinSeverity` | `1` ошибки, `2` +замечания, `4` всё |
| `diagOnlyCurrentMethod` | показывать замечания только текущего метода |
| `geometry` | последняя позиция и размер окна |
| `compact` | окно свёрнуто до одной строки |
| `claudeCommand` | `claude` — когда CLI разрешат; тогда ответ придёт в `context\reply.md` |
| `claudeMcpConfig` | путь к `mcp.json` с вашими MCP-серверами |

## Диагностика проблем

- Окно Конфигуратора не видно — запустите Python от администратора, если 1С
  запущена от администратора.
- Панель замечаний застряла на «запускается…» — смотрите `context\bslls.log`.
- Замечаний слишком много — снимите галку «только этот метод» наоборот,
  или переключите кнопку справа на «только ошибки».

## Внешний навигатор по конфигурации (необязательно)

Скрепка видит только открытый модуль. Всё, что за его пределами — общие модули,
метаданные, кто ещё зовёт этот метод, — ей недоступно.

Если у вас есть локальный сервис, который это знает (например MCP-сервер поверх
выгрузки конфигурации), укажите `navigatorName` и `navigatorUrl` — в шапке
появится индикатор «жив или нет». Сам запрос к нему делает агент, а не скрепка:
её дело — собрать контекст и не соврать о том, чего она не видела.

Без этого всё работает, просто агент будет знать ровно то, что в модуле.

## Что не попадает в репозиторий

`.gitignore` намеренно исключает всё, куда затекает ваш рабочий код:
`context\` (текст модуля, позиция курсора, журналы), `probe_1c_result.json`
(там же имя окна и пользователя), `answer.bsl` и `clip.config.json`.

Если поднимаете форк — проверьте это до первого коммита. Текст модуля 1С
из рабочей базы утекает удивительно легко.
